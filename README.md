# 과제8 · 소개 페이지에 패스키 달기

과제1의 공개 소개를 유지하고, 소유자의 비공개 자료를 패스키로 보호하는 프로젝트입니다. 서비스 비밀번호 입력·공개 회원가입은 없습니다.

- **결과물:** https://project-apprenticeship-08.vercel.app
- **public 소스:** https://github.com/jkimsvsd-code/project-apprenticeship-08
- **인증 구현 설명서:** [요구된 6항목](docs/authentication-report.md)
- **최종 점검:** [필수 47개·U1–U6](docs/final-audit.md) / [실제 HTTPS 요청·응답·공개키](evidence/deployment/https-verification.json)

심사자는 첫 화면과 공개 기록만 확인하면 됩니다. 패스키 등록이나 관리자 계정 제공을 요구하지 않습니다. 실제 소유자의 패스키·초기 등록 링크는 제출물에 포함하지 않습니다.

## 짧은 확인 방법 · 4줄

어디로 가나요: 위 결과물 HTTPS 주소에서 공개 소개를 열고, 소스 주소의 인증 구현 설명서를 확인합니다.\
세 단계 안에 무엇을 하나요: 공개 소개 열기 → ‘내용 검토 - 관리자 전용’ 버튼으로 로그인 화면 확인 → 설명서에서 성공·거절 요청 비교.\
무엇이 보이면 통과인가요: 기존 소개는 인증 없이 보이고 비공개 내용은 숨겨지며, 설명서에 미인증·타인 자료·질문 재사용·삭제 키의 거절 기록이 있습니다.\
안 될 때는 무엇이 보이나요: 미지원·취소·시간 초과·연결 실패 안내와 재시도 버튼이 보이며, API는 미인증 401·타인 자료 403·잘못된 인증 400을 반환합니다.

## 현재 동작

- 공개 페이지는 과제1의 본문·경험 상세 3개를 보존하고, 관리 기능 진입은 **‘내용 검토 - 관리자 전용’** 버튼 하나로 정리했습니다.
- 미로그인 상태에서 버튼을 누르면 `/login?next=%2Fvault`로 바로 이동합니다. 실제 패스키 인증 성공 후 본인 자료가 열립니다. 로그인 상태에서는 `/vault`로 바로 이동합니다.
- 계정마다 프로젝트 메모·지원 계획·학습 회고의 가상 자료 3개가 생성됩니다. 화면 숨김뿐 아니라 서버에서 세션·소유권을 검사합니다.
- 패스키 이름·등록일·사용자 메모·현재 로그인 키를 표시하고 추가·삭제를 제공합니다. 삭제한 키의 세션을 폐기하고 마지막 키 삭제는 차단합니다.
- 매번 새 질문을 발급하고 한 번만 소비합니다. 등록·인증은 실제 SimpleWebAuthn으로 검증합니다.

개인 공간과 검증 자료는 실제 연락처·신분증 번호 없이 만든 가상 내용입니다. 공개 소개는 [사용자가 지정한 과제1 원본](https://github.com/jkimsvsd-code/project-apprenticeship-01)의 공개 내용을 보존했습니다. [원본 출처·SHA](docs/baseline/assignment01/README.md).

## 필수 요구사항과 U1–U6의 확인 범위

필수 기준은 PDF의 C01–C03·C10–C53, 총 47개입니다. [항목별 추적표](docs/requirements.md)에 상태와 근거를 연결했습니다. 구현·자동 검증과 사용자의 실제 기기 확인, 과제 제출은 구분합니다.

| 추가 UX | 현재 구현과 검증 |
| --- | --- |
| U1 환경 안내 | HTTPS·지원 여부와 사용할 수 없는 환경 안내 |
| U2 진행·재시도 | 중복 요청 차단, 취소, 60초 시간 초과, 새 질문으로 재시도 |
| U3 목적지 복귀 | 관리자 버튼 → 로그인 → 자료, 로그인 상태의 직접 진입, 외부 목적지 제한 |
| U4 예비 키 | 한 개일 때 추가 안내, 두 번째 키 등록·목록 갱신, 동기화와 독립된 키 구분 |
| U5 삭제 | 삭제 후 남는 개수·확인/취소·키 세션 폐기·마지막 키 차단 |

[최종 결과와 미확인 항목](docs/final-audit.md)을 함께 확인하세요. 자동 검증은 Chromium CDP 가상 인증기로 실제 HTTPS·Neon DB·서명 검증을 수행합니다. 물리 기기·실제 저장 제공자의 등록·복구를 검증한 것으로 해석하지 않습니다.

## 패스키 저장소와 두 번째 키

**패스키 관리 → 패스키 추가 → 예비 패스키 등록**을 누른 뒤, 브라우저·기기 인증 창의 ‘다른 옵션/다른 방법’에서 기존과 다른 저장소나 패스키 지원 보안 키를 선택합니다. 원하는 저장소가 없다면 그 저장소를 지원하는 브라우저나 기기에서 기존 키로 로그인한 뒤 추가합니다.

QR은 다른 기기를 연결하는 경로입니다. 다른 기기라도 같은 Google·iCloud 계정으로 동기화된 기존 키가 있으면 중복으로 인식될 수 있습니다. 등록 후 목록이 2개인지 확인하고, 로그아웃 후 새 키로 로그인해 확인합니다.

‘저장소 메모 남기기’는 선택적인 사용자 기록입니다. 값을 바꿔도 실제 저장소가 바뀌지 않으며, 서비스가 제공자를 확인했다는 뜻도 아닙니다. 실제 저장처는 기기나 비밀번호 관리자의 패스키 목록에서 사이트 주소로 확인합니다. 자동 검증의 저장 위치는 Chrome CDP 소프트웨어 인증기이며 실제 소유자의 제공자 확인과 별개입니다.

## 기술 스택과 운영

React · TypeScript · Vite · Express · SimpleWebAuthn · Node.js 24 · 로컬 SQLite / 운영 Neon PostgreSQL · Vercel(sin1) · Playwright · axe-core.
버전은 package-lock.json에 고정했습니다. [선정 근거](docs/stack.md), [배포·관리 안내](docs/hosting.md), [폴더 트리](docs/structure.md).

| 화면 | 역할 |
| --- | --- |
| `/` | 과제1 공개 소개와 관리자 검토 버튼 |
| `/login` | 패스키 로그인과 허용된 목적지 복귀 |

## 로컬 재현

Node.js 24와 npm이 필요합니다. 기본 주소는 http://localhost:3000 입니다.

```sh
nvm use
npm ci
cp .env.example .env
npm run dev
```

별도 터미널에서 `npm run bootstrap -- --account owner --name "가상 사용자"`로 **로컬용** 첫 등록 링크를 만듭니다. 링크는 15분 동안 한 번 교환하며 등록을 완료해야 계정·공개키·자료가 확정됩니다. 등록을 취소하면 계정·키는 생성되지 않고, 임시 등록 준비는 만료 관리됩니다.
등록된 계정의 초기 링크는 재발급하지 않습니다. 로그인 후 예비 키를 추가합니다. 모든 키 상실 시 자동 복구는 없습니다.

Windows는 환경 파일을 직접 복사하고 같은 npm 명령을 실행합니다. SQLite는 `runtime/app.sqlite`에 저장됩니다. 실제 환경변수·DB·초기 링크·인증 원문은 Git에서 제외합니다.

운영 초기 등록은 서버 전용 환경변수가 있는 관리 환경에서 `npm run bootstrap:postgres -- --account owner --name "가상 사용자"`를 사용합니다. Vercel은 영속 Neon DB를 사용하며 임시 함수 디스크에 SQLite를 두지 않습니다. 자세한 명령은 [배포 안내](docs/hosting.md)에 있습니다.

## 재검증

```sh
npm run check
npm run test:production
npx playwright install chromium
npm run test:e2e
```

단위·HTTP 10개와 브라우저 시나리오 3개, 형 검사·빌드·운영 스모크 검사를 통과했습니다. 설치된 Chrome은 `PLAYWRIGHT_CHANNEL=chrome npm run test:e2e`로 사용할 수 있습니다. E2E는 localhost:4318의 `runtime/e2e/`만 초기화합니다.

운영 관리자 환경에서만 실행하는 최종 검증:

```sh
PLAYWRIGHT_CHANNEL=chrome node --env-file=.env.production.local --import tsx scripts/verify-deployment.ts
PLAYWRIGHT_CHANNEL=chrome node --env-file=.env.production.local --import tsx scripts/verify-deployment-ux.ts
```

실행별 새 가상 계정만 사용하고 끝나면 해당 계정을 정리합니다. 실제 소유자 키·자료는 수정하지 않습니다. 요청 횟수 제한이 있으므로 연속 실행하지 않습니다. 가상 인증기의 개인키는 메모리에서만 다루고 공개 증거에 저장하지 않습니다.

## AI와 내 판단 · 3줄

AI에게 맡긴 일: 스택 비교, 과제1 소개 보존, 패스키·세션·자료 격리·U1–U6 구현, 테스트·배포·공개 검증 기록과 문서 정리.\
내가 직접 판단한 일: 필수 요구사항·U1–U6과 기본 정책 승인, 과제1 원본 지정, GitHub public·HTTPS 공개, 관리자 전용 버튼과 로그인 후 자료 진입 방식 결정.\
AI 제안을 따르지 않은 일: 저장 위치가 실제 선택 설정처럼 보이던 초안을 기록용 메모로 바꾸도록 요청했고, 개인 공간 홍보·메뉴 대신 관리자 전용 버튼만 남기도록 수정 요청함.

위 내용은 대화에서 확인된 결정만 기록했습니다. 실제 패스키 저장 위치·물리 기기 검증과 과제 제출 여부는 사용자가 확인해야 합니다.
