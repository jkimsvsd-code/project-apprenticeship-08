## 재현·보관 상태

- `npm run check`: 단위·HTTP 10개, 형 검사·클라이언트/서버 빌드 통과.
- `npm run test:production`: 컴파일된 운영 진입점·정적 자산·CSP·보안 쿠키·관리 CLI 스모크 통과.
- `PLAYWRIGHT_CHANNEL=chrome npm run test:e2e`: 3개 시나리오 통과. API·WebAuthn·UX와 실제 서명 검증을 포함.
- 두 운영 검증 스크립트의 생성 계정은 모두 정리했습니다. 소유자 계정·키·자료는 유지했습니다.
- 공개 증거에서 초기 링크·쿠키·토큰·개인키·실제 DB 연결값을 제외합니다. 환경변수와 실제 DB는 Git/배포 입력에서 제외합니다.

과제의 상세 47개 항목은 [추적표](requirements.md), 제출 문구는 [README](../README.md)와 [제출 안내](submission.md), 기술 한계는 [인증 설명서 ⑥](authentication-report.md)에 있습니다.

## 후속 등록 방식 보강

사용자의 iPhone 저장 보고를 반영해 실제 WebAuthn 등록 방식 선택을 추가했습니다. 기기 내·다른 기기(QR)·보안 키·브라우저 선택이 각각 options의 attachment/hints에 반영됩니다. 회사별 제공자를 지정하거나 iCloud·Google 실물 저장을 자동으로 증명하지는 않습니다. 최종 운영 증거의 registrationMethods 항목을 확인하세요.

최신 등록 경로 검증: HTTP 통합과 운영 JSON의 registrationMethods에서 4개 방식의 attachment/hints, 기존 키 제외·UV 유지가 확인됐습니다. 실제 서명 흐름은 internal·USB 가상 인증기로 검증했습니다. actualGoogleOrIcloudProviderVerified는 false입니다.
