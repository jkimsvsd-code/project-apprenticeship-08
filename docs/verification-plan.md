# 검증 계획

상태: Node·HTTP·Chromium 가상 인증기 검증을 구현·실행했습니다. 최근 결과는 verification-results.md와 evidence/를 확인합니다.

## 준비와 실행 범위

- 전용 테스트 DB에서 첫 등록을 완료해 A·B와 서로 다른 자료를 생성합니다. tests/fixtures/에는 가상 예시를 별도로 보관합니다.
- A에 별도 패스키 2개, B에 최소 1개를 실제로 등록합니다. fixture는 패스키를 포함하지 않습니다.
- 자동 테스트용 가상 인증기를 사용할 경우 실제 기기·제공자 검증과 구분해 기록합니다.
- 자동화만으로 확인하기 어려운 패스키 저장 위치·운영체제 UI·접근성은 직접 확인합니다.
- 실행 환경·실행 시각·커밋을 기록하고, 공개할 증거에서 비밀값을 제거합니다.

## 필수 4가지 검증

| 검증 | 성공 사례 | 거절 사례 | 증거 위치 |
| --- | --- | --- | --- |
| 로그인 없이 열기 | A가 로그인해 자기 자료 조회 | 미인증 직접 API 요청 401/403; 페이지 소스에도 자료 없음 | evidence/authorization/ |
| 남의 패스키로 열기 | A·B 각각 자기 자료 조회 | A→B, B→A 자료 직접 요청 거절; 전후 자료 건수 동일 | evidence/authorization/ |
| 이미 쓴 질문 재사용 | 새 질문과 정상 서명으로 로그인 | 이미 사용한 질문·인증 응답 재전송 거절 | evidence/authentication/ |
| 패스키 삭제 뒤 로그인 | A의 남은 패스키로 로그인 | 삭제한 패스키의 인증 거절 | evidence/passkey-lifecycle/ |

서로 다른 요청·응답을 같은 문서에 나란히 기록합니다. 정상 흐름을 깨뜨리지 않는 분리된 검증 환경에서 실행합니다.

## 추가 필수 확인

- 등록·로그인 질문을 각각 두 번 이상 발급해 값이 다름을 기록합니다.
- 등록 응답 본문과 저장된 공개키를 확인하고, 서비스에 개인키가 전달되지 않음을 설명합니다.
- 등록 취소 후 계정·credential이 확정되지 않았음을 확인합니다. 임시 질문 정리도 확인합니다.
- 서명·Origin·RP ID·만료한 질문을 변조한 경우의 거절을 확인합니다.
- 본인 목록 요청의 계정값을 변조해도 세션 사용자 자료만 반환하는지 확인합니다.
- 로그아웃 전 쿠키를 로컬에서 재사용해도 거절되는지 확인합니다. 쿠키 원문은 공개하지 않습니다.
- 타 계정 패스키 삭제와 마지막 패스키 삭제를 거절하는지 확인합니다.
- 미인증 HTML·API·직렬화 데이터·공개 번들 및 로그아웃 후 화면에 비공개 자료가 남지 않는지 확인합니다.
- U1–U6의 정상·취소·실패·모바일·키보드 동선을 확인합니다.

## 테스트 분류

| 위치 | 검증 대상 |
| --- | --- |
| tests/unit/ | 질문 만료·소비, 소유권 판정, 내부 복귀 경로 등 독립 규칙 |
| tests/integration/ | 등록·서명 검증, 세션 폐기, 계정 격리, 삭제 정책과 실제 저장소 연동 |
| tests/e2e/ | 공개 첫 화면, 잠긴 공간, 등록·로그인·로그아웃, 패스키 관리와 U1–U6 |

npm test는 Node 단위·HTTP 테스트, npm run test:e2e는 Playwright 브라우저 테스트입니다. E2E는 runtime/e2e/만 초기화하고 정상 DB에는 쓰지 않습니다.

등록 요청에는 실제 개인키가 포함되지 않으며, CDP로 복제한 가상 인증기 상태는 테스트 프로세스 메모리에서만 다룹니다. 서명 카운터의 최신 상태를 보존하며 오래된 복제 상태가 거절되는 것을 오류로 무시하지 않습니다.
